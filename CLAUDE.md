# CLAUDE.md

A small agentic simulation platform built on the Full Stack FastAPI Template. A user submits a
study, a Pydantic AI agent runs a Prefect-wrapped simulator as a background job, and the React UI
polls for the result. The app is deliberately small; **the test layer around it is the point of the
project**. See `README.md` for features and architecture, and `TESTING.md` for the test inventory.

## Direction (read this first)

The pipeline simulator and Studies feature are being replaced by **Patch & Pantry**, a local
food planner: best buy for produce across stores, farm-share and market value checks, and
grow-or-buy planning, for one household in North Alabama, growing toward food independence. The
Studies code stays working until Phase 1 replaces it; it is the reference for the platform's
patterns.

- `docs/design.md`: what to build and why. **Source of truth** for product decisions.
- `docs/roadmap.md`: phases, tasks, and gates. Tick tasks in the PR that completes them.
- `docs/specs/phase-N.md`: the spec for the current phase. Implement from the spec; if it is
  missing or unclear, write or update it first and ask the owner to review.
- `docs/specs/known-answers.md`: verified numbers for unit tests and golden evals.
- `backend/app/seed_data/`: reference data with provenance (`README.md` there).
- `scripts/data/`: data build scripts and prototypes.

## Layout

- uv workspace (root `pyproject.toml`, member `backend/`, package `app`) and bun workspace
  (root `package.json`, members `frontend/`, `packages/*`). Run Python tools with `uv run`, JS
  tools with `bun`/`bunx`. Do not use pip or npm to add dependencies.
- `backend/app/`: FastAPI app. Studies feature: `api/routes/studies.py`, `study_jobs.py`,
  `agents/` (`study_agent.py`, `simulator.py`, `demo_model.py`).
- `frontend/src/`: React 19, TanStack Router (file routes) and Query, Tailwind, shadcn/ui.
  Studies UI is in `components/Studies/`.
- There is one application image: `backend/Dockerfile` builds the SPA and FastAPI serves it from
  `backend/app/frontend` (generated, do not edit). No separate frontend container.

## Rules and gotchas

- **Regenerate the API client after any backend API/model change:** `bash scripts/generate-client.sh`.
  Never hand-edit `frontend/src/client/` (generated by `@hey-api/openapi-ts`).
- **Schema changes need an Alembic migration** in `backend/app/alembic/versions/`
  (`uv run alembic revision --autogenerate -m "..."` from `backend/`). It must downgrade cleanly:
  CI runs every migration down and back up, then `alembic check`. SQLModel table models skip
  validation, so put rules that matter in CHECK constraints (see the food planner tables).
- **Backend tests share the dev database and delete all users when they finish.** Rerun
  `scripts/prestart.sh` afterwards before using the app or running E2E tests.
- **Tests must never call a real model.** `tests/conftest.py` sets `ALLOW_MODEL_REQUESTS = False`.
  Inject `TestModel`/`FunctionModel` via `app.dependency_overrides[get_study_model]` (API tests)
  or `study_agent.override(...)` / `reviewer_agent.override(...)` inside the test body (agent
  tests; override both when delegation is involved). Use `FakeSimClient` from
  `tests/agents/conftest.py` instead of the real simulator.
- `SIM_MODEL` is a `Settings` field (default `demo`, deterministic scripted responses); the model
  is built when a run starts, not at import. Other values: `test`, `foundry:deepseek-v3.2`.
- Every exit path in `study_jobs.execute_study` must leave a study in `succeeded` or `failed`;
  a study stuck in `running` makes the UI poll forever. Each path also sets `study.status` on the
  `study` span.
- Tracing (`app/core/tracing.py`) is off unless `PHOENIX_COLLECTOR_ENDPOINT` is set. Agent
  instrumentation is global (`Agent.instrument_all`), so tests that call `setup_tracing` must call
  `shutdown_tracing` afterwards; use the `SnapshotExporter` in `tests/utils/tracing.py`.
- Idempotency keys live in Redis, scoped per user (`idempotency:studies:{user_id}:{key}`), 24 h TTL.
  Users may read only their own studies.
- `TestClient` runs background tasks before returning, so API tests are synchronous by design.
- When adding a test for a behavior, check it fails with the bug introduced (see "Checking that the
  tests catch bugs" in `README.md`), and record notable changes in `TESTING.md`.

## Rules for the food planner

These come from `docs/design.md`; follow them in every change.

- **Numbers come only from deterministic tools.** The model extracts input, asks questions,
  chooses tools, and explains; it never computes prices, quantities, yields, or dates. Every
  number in an answer must match a tool output (a nightly trace check enforces this).
- **Units:** store grams of the edible part; show cups (the federal produce definition). Do not use
  the word "serving" in the UI. Money is integer cents (pending owner review of the Phase 0 spec).
- **Not a dieting app:** no meal logging, portion tracking, or body measurements. "Actual" means
  produce acquired (bought, farm share, harvested), never food eaten. Explanations avoid dieting
  language.
- **Minimal personal data:** household members are anonymous rows with only a calorie level. No
  names, ages, sex, weight, or height. Location is a region or ZIP, never a street address. No
  third-party analytics or ad trackers.
- **Prices are private by default** and record owner, visibility, source type, region, and a sale
  flag. AMS report prices are sale prices: never present them as shelf prices.
- **Reference data is versioned:** never overwrite a data snapshot (a trigger rejects `UPDATE` and
  `DELETE` on `data_snapshot`); every run and plan records the snapshot versions it used. Raw
  downloads in `data/sources/` are kept byte for byte (`.gitattributes`, pre-commit excludes):
  never re-save or reformat them. Loaders match source rows only through
  `backend/app/seed_data/catalog_crosswalk.csv` (and piece weights through `catalog_portions.csv`),
  which the owner reviews. Every catalog fact has a source, including "stand-in" when it
  borrows another item's.
- **Derived North Alabama planting dates are unverified** (`verified=False`); never use them as
  golden answers until checked against Extension's ANR-1165 table.
- **Photos are never stored.** CI fixture photos must be the owner's own or made up, because the
  repository is public.
- **DeepSeek-V3.2 on Microsoft Foundry** is the only live model for now (Claude on Foundry needs
  an enterprise Azure subscription). Build models through the factory (Phase 0) with
  `OpenAIChatModel` and `AzureProvider` (`app/agents/models.py`). The factory pins the default
  deployment name's full profile (a partial `profile=` is merged and does not override a custom
  name's generic one); it passes the endpoint and key from `Settings`, never through
  `AZURE_OPENAI_*` variables, and accepts only a v1 endpoint. Secrets such as `FOUNDRY_API_KEY` go
  in the gitignored `.env.local`, never in the committed `.env`; never set
  `temperature`, `top_p`, or `top_k`; construct clients lazily so importing `app` needs no Foundry
  settings. DeepSeek-V3.2 reads text only, and no LLM-as-judge checks run until a second model
  exists.
- **No live model calls in PR CI.** Live calls run nightly only. The budget is 200 USD a month;
  measure tokens with Phoenix.

## Keeping the docs current

- `docs/` in this repository is the source of truth. The claude.ai copies of the design doc and
  roadmap are frozen snapshots from 2026-11-11; do not update them.
- When a decision changes, edit `docs/design.md` and add a row to its change log in the same PR.
- When a task is done, tick it in `docs/roadmap.md` in the same PR; record plan changes in the
  roadmap's change log.
- New verified numbers go in `docs/specs/known-answers.md`; new reference data goes in
  `backend/app/seed_data/` with a row in its `README.md`.

## Working with the owner

- Explain the reasoning behind a recommendation, and keep sourced facts separate from inference.
  Cite a source (link) for any external data or claim.
- Prefer showing a worked example or a diagram over a long description.
- Ask before choosing among options that change the design; record the answer in
  `docs/design.md`.

## CI

PRs run: Test Backend (coverage gate 90%), Playwright (4 shards, demo mode,
`--fail-on-flaky-tests`), Test Docker Compose, pre-commit (auto-commits fixes to same-repo PRs),
and zizmor. Actions are pinned to commit SHAs with `persist-credentials: false`; keep that
pattern when editing workflows. The FastAPI Cloud deploy in `deploy.yml` is disabled (`if: false`).

## Git

Branch off `master` for changes and open a PR; don't commit directly to `master`.
